# Практическая работа 15

Модульное тестирование функций.

Написаны табличные тесты Sum и Divide, подтесты Clip и тест сервиса с репозиторием через интерфейс. Проверяются отрицательные числа, деление на ноль, пустые строки, границы max и Unicode. Стаб проверяет успешный поиск, отсутствие пользователя, ошибку репозитория и переданные аргументы.

## Запуск на macOS или Linux

Go 1.27.1, curl. Каждая практика — отдельный Go-модуль. Команды выполняются из этой папки.

```bash
go test ./...
go vet ./...
go test -race -v -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
```

Файл `.env` читается оболочкой через `source`; автоматически сервер его не загружает. Порт API по умолчанию 8080. При одновременном запуске меняйте HTTP_ADDR, APP_ADDR (ПР9) или APP_PORT (ПР10).

## Проверки

Фактические результаты находятся в `evidence/`. Полные curl-команды и ответы — в `evidence/requests.txt` (для практик с HTTP-проверками). Тесты 15 и 16 записаны в `evidence/tests.txt` и `evidence/integration.txt`.

## Подготовка к защите

Unit-тест изолирует один блок, интеграционный проверяет связь компонентов и реальную БД.

Табличный тест хранит входы и ожидаемые результаты в срезе. t.Run даёт отдельное имя каждому сценарию.

require прерывает текущий тест при ошибке; assert продолжает. Чистого testing достаточно для простых проверок.

Coverage считает исполненные statements, но не качество утверждений. Здесь каждая ветка сопровождается проверкой результата или ошибки.

Для ошибок проверяют ErrorIs и нулевой результат. Стаб подменяет зависимость и позволяет воспроизвести ошибки без БД.
